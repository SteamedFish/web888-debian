# Union of the push.paths of every deb-publishing workflow:
#   build-boot-deb.yml, build-kernel-deb.yml, build-redpitaya-deb.yml,
#   build-websdr-deb.yml, build-thirdparty-debs.yml, build-web888d-deb.yml
#
# Consumed by build-image.yml's preflight job via matches-deb-triggers.sh:
# a push touching any of these paths fires deb builds whose publish step
# dispatches `debs-published`, so the push-triggered image build is skipped
# (it would otherwise install the STALE published debs and test a
# combination that never ships — the image rebuild arrives via the dispatch
# once the fresh debs are in the APT repo).
#
# EXCEPTION — build-web888d-deb.yml (optional web888d / web888-ng bitstream):
# its publish step deliberately does NOT dispatch `debs-published` (these
# are maintainer packages outside the fixed image package list, so an image
# rebuild would test nothing new). Pushes touching only its paths skip the
# image build with NO deferred rebuild — that is intended: maintainer
# package updates are not image triggers.
#
# KEEP IN SYNC with those workflows' push.paths. Drift consequences:
#   txt MISSING a deb path  → push fires both deb build and image build
#                             (duplicate work, the pre-2026-08-18 behavior);
#   txt EXTRA patterns      → image build skipped while no deb build fires
#                             (no image validation; recover via manual
#                             workflow_dispatch).
#
# Syntax mirrors GitHub Actions push.paths as used by those workflows:
# one pattern per line — exact path, or 'dir/**' (everything under dir/).
# Blank lines and '#' comments are ignored.
